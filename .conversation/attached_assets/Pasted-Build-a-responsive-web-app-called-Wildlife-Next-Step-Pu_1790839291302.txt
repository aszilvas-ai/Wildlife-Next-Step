Build a responsive web app called “Wildlife Next Step.”

Purpose: help a person who finds a possibly injured or orphaned wild animal understand the safest next action. This is a school prototype, not a real wildlife-care service.

Design:
- Calm, trustworthy, mobile-first interface.
- Colors: forest green, cream/off-white, muted tan, and small amber accents for cautions.
- Use clear cards, rounded corners, readable large text, and a simple progress indicator.
- Homepage headline: “Found wildlife? Start with the safest next step.”
- Add a visible disclaimer: “For a class prototype only. This does not diagnose animals or replace a licensed wildlife rehabilitator.”

Main flow:
1. A user begins an “Animal encounter” form.
2. Ask for: Indiana location/county, time of day, likely animal type, size/appearance, visible injury, whether a parent was seen, and actions already taken.
3. Show a “Review what we heard” page where the user can edit their answers.
4. Show one of three result cards:
   - “Leave it alone and observe”
   - “Contact a wildlife rehabilitator”
   - “Short-term safe holding while arranging professional help”
5. Every result must show:
   - Why this route was selected
   - A “What to do next” checklist
   - Safety notes
   - A source/citation area
   - A button to restart

Safety requirements:
- Use fictional demo cases only; do not collect or save real user data, photos, or exact locations.
- Do not diagnose animals, confirm species, prescribe medication, recommend feeding, or give treatment instructions.
- For unclear, conflicting, or high-risk situations, default to “Contact a wildlife rehabilitator.”
- Include “Call before transport” on contact-related results.
- Clearly state that a listed contact does not guarantee availability.

Demo content:
- Create a small fictional Indiana rehabilitator directory with name, county, animal specialty, phone number, and listed hours.
- Create these three test scenarios:
  1. A nearly full-sized squirrel with a fluffy tail that can run, jump, and climb, with no injury.
  2. A bleeding squirrel that needs professional help.
  3. A baby squirrel not retrieved by dusk, where the prototype directs the user to contact a professional and displays only approved, non-treatment holding guidance.
- Add a simple rule-based routing system for these scenarios. Structure the code so an AI service could later summarize user descriptions and ask follow-up questions, but do not connect a real AI API yet.

Technical requirements:
- Use React with a clean component structure.
- Keep all demo data and routing rules in easy-to-edit local files.
- Include a polished landing page, multi-step intake form, review page, results page, and a small “How this prototype works” section.
- Make it work well on phones and desktops.
